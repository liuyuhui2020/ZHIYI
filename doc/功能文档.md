> 状态：功能设计基线；Model Gateway、Run Lifecycle Kernel、PostgreSQL RunRepository 与 Worker Lease Kernel 已实现，完整 Runtime 尚未实现
> 版本：v0.1
> 更新日期：2026-08-27
> 关联文档：[需求文档](./需求文档.md) · [技术方案](./技术方案.md) · [项目计划](./PROJECT.md)

## 1. 文档说明

本文从使用者角度描述平台提供的功能、主要流程、输入输出和异常行为。本文不是 API 字段参考，接口路径与 Schema 将在实现阶段通过 OpenAPI 和 Python SDK 进一步固化。

功能阶段标识：

- **M0**：Runtime Alpha。
- **M1**：Platform Beta。
- **M2**：Production V1。

## 3. 主要用户流程

### 3.1 开发者定义并发布 Agent

1. 开发者使用 Python SDK 创建 AgentSpec。
2. AgentSpec 声明模型能力、Tool、Context Policy、Memory Policy、预算和结果 Schema。
3. 平台执行静态校验：Tool 是否存在、模型能力是否兼容、Prompt 是否可解析、预算是否合法。
4. 开发者运行单元测试和评测集。
5. 平台生成不可变 AgentVersion。
6. 达到评测门禁后，AgentVersion 被标记为 `released`。

异常行为：

- Tool 未注册：发布失败。
- 模型缺少必要能力：发布失败并指出缺失能力。
- Prompt 版本不可用且没有回退：发布失败。
- 关键安全评测回退：不得发布。

### 3.2 用户提交任务并查看结果

1. 客户端在 Session 中创建 Task 和 Run。
2. API 返回 `run_id` 和事件地址。
3. 客户端通过 SSE 接收排队、运行、消息、Tool、审批、Artifact 和终态事件。
4. 断线后，客户端使用最后事件序号继续接收。
5. Run 完成后，客户端获取结构化 RunResult。

用户可以看到过程状态，但看不到原始 Chain-of-Thought。

### 3.3 审批写操作

1. 模型提议调用写 Tool。
2. 平台校验 Tool 参数并执行 Policy Engine。
3. Policy 返回 `require_approval`，Run 进入等待状态。
4. 有权限的审批人员看到目标 Tool、参数摘要、风险、上下文和过期时间。
5. 审批人员批准、修改或拒绝。
6. 修改后的参数重新校验。
7. 批准后执行 Tool；拒绝后将受控结果返回 Agent Loop。

### 3.4 Worker 故障恢复（后续能力）

1. Worker 领取 Run 并持续续租。
2. Worker 在节点执行间保存 LangGraph Checkpoint，并持久化产品事件。
3. Worker 异常终止后租约过期。
4. 其他 Worker 领取 Run，从 Checkpoint 恢复。
5. 已完成的 ToolInvocation 直接复用结果。
6. 结果未知的写操作进入人工处理，不自动重试。

当前 Feature 006 只实现上述流程所需的 PostgreSQL 租约协调与 fencing 持久化边界，
不启动 Worker、不执行 Agent 节点、不写 Checkpoint，也不自动接管或恢复失效 Run。

## 4. Agent 管理

### 4.1 AgentSpec

AgentSpec 是常规 Agent 的声明式入口，包含：

- 名称、说明和标签。
- 默认模型与兼容 Fallback。
- Tool 列表与权限要求。
- Prompt 引用。
- Context 和 Memory Policy。
- Loop、Token、成本和时间预算。
- 是否启用结构化 Planning。
- RunResult 扩展 Schema。

AgentSpec 不直接暴露数据库实体，也不包含运行时密钥。

### 4.2 自定义 Graph

复杂 Agent 可以注册自定义 StateGraph。自定义 Graph 仍必须：

- 接受平台定义的运行上下文。
- 使用平台 Model、Tool、Memory 和 Event 端口。
- 遵守预算、取消和租户隔离规则。
- 不直接修改产品数据库。
- 产生平台可识别的终态结果。

### 4.3 AgentVersion

AgentVersion 固定：

- AgentSpec 或 Graph 版本。
- Prompt 版本和内容摘要。
- Tool 名称与版本。
- 模型与能力要求。
- Context、Memory、Policy 和预算摘要。
- 代码或 Agent Package 摘要。

Run 创建后不能切换 AgentVersion。等待审批的旧 Run 也必须由兼容旧版本的 Worker 恢复。

## 5. Run Runtime

### 5.1 Run 状态

| 状态 | 说明 | 是否终态 |
|---|---|---|
| queued | 已持久化，等待 Worker | 否 |
| running | Worker 正在执行 | 否 |
| waiting_approval | 等待审批 | 否 |
| waiting_resolution | Tool 结果未知，等待人工处理 | 否 |
| succeeded | 成功产生 RunResult | 是 |
| failed | 不可恢复失败 | 是 |
| cancelled | 被授权用户取消 | 是 |
| limit_exceeded | 达到硬预算 | 是 |

当前已实现的生命周期内核固定 Run 的 AgentVersion，并以不可变快照、连续版本和连续
事件序号推进状态。命令先按租户与 command_id 检查意图指纹，再校验 expected_version；
相同命令重放原收据，不同意图复用同一标识稳定冲突。

取消与 deadline/预算超限矩阵如下：

| 当前状态 | 可取消 | deadline/预算超限 |
|---|:---:|---|
| queued | 是 | 转为 limit_exceeded |
| running | 是 | 转为 limit_exceeded |
| waiting_approval | 是 | 转为 limit_exceeded |
| waiting_resolution | 是 | 转为 limit_exceeded |
| succeeded / failed / cancelled / limit_exceeded | 否，保持终态 | 保持原终态 |

### 5.2 预算

默认预算：

- 最大运行时间：30 分钟。
- 最大步骤：50。
- 最大模型调用：20。
- 最大 Tool 调用：50。
- 最大 Subagent 深度与数量：由 AgentVersion 显式配置。
- Token 和成本：由租户与 AgentVersion 共同限制。

平台可允许租户设置更严格限制，不允许普通 Run 放宽平台硬上限。

当前内核接收已经合并的有效硬预算，不负责选择上述默认值。次数和 Token 使用非负整数，
成本只接受有限非负 Decimal；等于上限允许继续，超过任一维度或到达 deadline 时在新工作
开始前终止，且不会把超限 charge 计入已确认用量。相同 charge_id 与相同内容不重复累计，
相同标识与不同内容返回幂等冲突。

### 5.3 当前实现边界

当前已提供 Python application/domain 契约、内存原子仓储和 PostgreSQL 18.6 持久仓储；事件
只包含受控状态、版本、用量、引用和安全错误码。RunResult 只允许显式提交且由上游策略
批准的最终答案、受控引用和安全错误，不保存 Prompt、Provider 原始响应或思维链。

PostgreSQL adapter 将 Run 快照、零或一个 Event 与 CommandReceipt 在单事务中提交，支持
跨进程同命令回放、连续事件分页和引擎重建后的领域值还原。结构变更必须由独立 Alembic
Job 显式执行；应用只读检查结构契约版本，不会自动建表或升级。提交确认未知时返回
`commit_outcome_unknown`，调用方只能以原 command_id 和原意图重放确认。

Worker Lease Kernel 已实现以下持久化行为：

- 只在租户内领取 `queued` Run；无竞争时按稳定 FIFO，竞争路径使用跳锁快路径和有界队头
  阻塞探测。每次调用最多返回一个 Run，不修改 Run 生命周期事实。
- 平台签发 UUIDv7 `claim_id`，相同标识和相同归一化意图在 24 小时窗口内精确回放
  `claimed` 或 `no_work`；相同标识不同意图冲突，过期标识不能领取新 Run。
- 租约使用 PostgreSQL 时间，允许 10–30 秒且默认 30 秒。完整权限证明包含 tenant、Run、
  Worker、claim、attempt、lease_version 与不可猜测 token；attempt/version 单调且永不重置。
- 读取权限、续租和释放都按当前完整证明判定。成功续租或释放只推进一次版本；重复请求只
  确认当前事实，不能按重试时刻盲目延长。释放立即撤销权限。
- Worker 产出的新生命周期写入必须使用 `commit_with_lease`，在同一事务中按 004 收据、Run、
  Lease、Event 顺序验证 fencing 并原子提交。已存在的相同 004 收据先回放；守卫失败不留下
  Run、Event、CommandReceipt 或 Lease 的部分变化。
- 领取、续租、释放或守卫提交在提交确认未知时不自动重试：领取只以原 claim/意图重放；
  续租/释放先读取同一证明确认版本与状态；守卫提交只以原 004 命令和意图收敛。
- 可按固定数据库 `as_of` 和稳定游标观察自然到期或主动释放的 `running` Run，但只返回最小
  恢复候选事实，不暴露 Worker/claim/token，也不修改、重排、接管或恢复 Run。

尚未实现 Worker 循环、LangGraph Checkpoint、REST、SSE、SDK 或后台恢复；当前能力仅证明
协调事实可在进程重启后安全读取和收敛，不代表任务会被后台重新领取或继续执行。成功领取
收据中的原始 replay token 尚无物理保留上限/静态加密设计，生产 PostgreSQL/NTP 时间偏差与
回拨监控也未建立，因此 006 不具备生产启用资格。

### 5.4 Planning

- 简单任务直接执行 Tool-Calling Loop。
- 复杂度策略命中后生成结构化 Plan。
- Plan 包含步骤、状态、依赖和预期输出。
- 步骤失败时允许局部修订，但不得无限添加步骤。
- Plan 更新通过事件对用户可见。

## 6. 模型功能

### 6.1 Provider

Model Gateway 独立切片已经实现 Fake、OpenAI 和 Anthropic Provider。平台契约统一
处理消息、流式输出、Tool Call、Structured Output、用量和安全错误，不向调用方
暴露 LangChain 或 Provider SDK 对象。该切片尚未接入 Agent/Run、预算持久化、Trace
或计费，因此不能独立视为 Runtime 交付完成。

### 6.2 能力配置

模型能力至少包括：

- 文本输入输出。
- Tool Calling。
- Structured Output。
- 最大上下文和输出 Token。
- 多模态输入类型。
- 是否提供可计费用量。

能力不匹配时，平台必须在调用前失败，而不是运行中静默降级。

### 6.3 Fallback

- 只处理明确可重试的错误。
- 先执行同模型有限重试，再进入兼容模型。
- 不因业务拒绝或无效 Tool 参数切换模型。
- Fallback 过程必须记录模型、原因、次数、Token 和成本。
- 流式调用只允许在首个文本或 Tool 增量前重试或 Fallback；首个可见增量后发生故障时直接结束，禁止从头重放。
- 调用总 deadline 覆盖限流等待、密钥解析、全部尝试、退避、Fallback 和流消费；调用方取消立即停止后续工作。

## 7. Context Engine

### 7.1 ContextItem

ContextItem 是上下文最小单元，具有类型、来源、内容引用、优先级、信任、敏感级别和 Token 估算。

### 7.2 组装规则

平台先计算模型输入预算并预留输出，再按固定优先级选择内容。必须保留的平台安全策略不能被裁剪。Tool 和检索结果视为不可信数据，除非经过明确可信转换。

### 7.3 Context Manifest

每次模型调用生成 Manifest，记录：

- 使用了哪些 ContextItem。
- 哪些内容被裁剪、摘要或拒绝。
- Token 估算与实际用量。
- Prompt、Memory、知识和 Tool 来源版本。

Manifest 用于调试和评测，敏感正文可被替换为摘要或哈希。

## 8. Memory

### 8.1 短期 Memory

- 维护当前对话需要的消息和结构化状态。
- 接近上下文限制时执行裁剪或摘要。
- 与 Graph Thread 绑定。
- 同一 Session 的独立 Task 默认不共享可变 Graph State。

### 8.2 长期 Memory

模型可以提出候选记忆，Memory Policy 根据类型、来源、敏感度、重复性和用户授权决定是否保存。

用户或管理员可以：

- 查看授权范围内的 Memory。
- 更正内容并保留修改审计。
- 删除指定记录、主体或命名空间。
- 配置保留期限。

## 9. RAG 与文档

### 9.1 文档摄取

M1 接受 TXT、Markdown 和 PDF，执行病毒/大小检查、文本提取、分块、Embedding 和索引。失败文档必须保留可诊断状态，不得只显示“上传失败”。

### 9.2 检索

检索请求包含租户、主体、Agent、任务、过滤条件和数量限制。结果必须经过权限过滤，并携带可追踪来源。

### 9.3 Citation

Citation 至少包含文档 ID、版本、标题和定位信息。前端可通过 Citation 打开有权限的源文档位置。

## 10. Tool 与审批

### 10.1 Tool 分类

| 分类 | 示例 | 默认行为 |
|---|---|---|
| read_only | 查询订单、读取知识 | 可有限重试；标记安全时可并行 |
| reversible_write | 更新可回滚草稿 | 按策略审批，串行执行 |
| irreversible_write | 发送、删除、支付 | 强审批，必须具备幂等或结果查询 |
| external_communication | 邮件、消息、外部系统写入 | 按数据敏感度和目标审批 |

### 10.2 ToolInvocation

ToolInvocation 保存请求、校验、策略、审批、执行和结果状态。敏感参数可以只保存加密内容、摘要或 Artifact 引用。

### 10.3 MCP

M2 支持从允许的 MCP Server 发现 Tool。发现不代表启用，租户管理员必须完成授权和风险配置。MCP 连接失败不得使 Runtime 整体不可用。

## 11. Artifact

Artifact 支持上传文件、Tool 大结果、生成报告和中间数据。用户只能通过短时授权地址访问。模型获得的是经过权限和内容策略筛选的文本或引用。

Artifact 状态包括上传、扫描、解析、可用、失败、过期和删除。解析失败不能删除原始文件，除非安全策略要求隔离。

## 12. Subagent

M2 的 Subagent 是受控委派：

- 主 Agent 选择平台注册的 SubagentVersion。
- 平台为其创建独立上下文和预算。
- 默认禁止写 Tool。
- 子任务结果以结构化对象或 Artifact 返回。
- 主 Agent 负责采用、拒绝或汇总结果。
- 达到深度、数量、时间或成本上限时停止委派。

## 13. API 与事件

### 13.1 REST 能力组

- AgentDefinition 与 AgentVersion 查询和发布。
- Session、Task、Run 创建与查询。
- Run 取消与重试。
- Approval 查询与提交。
- Memory 查询、更正与删除。
- Artifact 上传、状态与下载授权。
- 健康、就绪和版本信息。

具体路径在实现阶段通过 OpenAPI 固化。

### 13.2 SSE 事件

| 事件 | 用途 |
|---|---|
| run.created / run.started / run.waiting_approval / run.waiting_resolution / run.resumed | 生命周期 |
| message.delta / message.completed | 用户可见消息 |
| plan.created / plan.updated | 结构化计划进度 |
| tool.requested / tool.started / tool.completed / tool.failed | Tool 生命周期 |
| approval.required / approval.resolved | 人工审批 |
| artifact.created | 生成物 |
| run.succeeded / run.failed / run.cancelled / run.limit_exceeded | 终态 |
| heartbeat | 维持连接与检测断线 |

客户端必须按事件 ID 去重，并将服务端终态作为最终依据。

上表中的 Run 事件名已经由 Python library 契约实现；SSE 传输、断线续传与公开 API
Schema 仍是后续 M0 切片，当前不得据此宣称网络接口可用。

## 14. 开发者控制台

### 14.1 Playground

选择 AgentVersion，创建测试 Session，查看实时事件、Citation、Artifact、用量和 RunResult。

### 14.2 Run 时间线

按时间展示节点、模型、Tool、审批、错误和恢复信息。只展示可解释状态，不展示原始思维链。

### 14.3 审批箱

展示待处理操作、参数摘要、风险、申请者、过期时间和关联 Run，支持批准、编辑和拒绝。

### 14.4 Memory 管理

按主体、Agent 和命名空间查看 Memory，支持更正、删除和来源追踪。

### 14.5 评测入口

展示 AgentVersion 发布状态和核心评分，详细 Trace 和实验跳转到 Langfuse。

## 15. 权限模型

M2 最小角色建议：

| 角色 | 主要权限 |
|---|---|
| tenant_owner | 租户全部配置与成员管理 |
| agent_developer | 定义、测试和提交 AgentVersion |
| releaser | 审核评测并发布版本 |
| operator | 查看 Run、处理运行故障和未知结果 |
| approver | 审批授权范围内的 Tool |
| requester | 创建和查看自己的 Session/Run |
| viewer | 只读查看授权资源 |

角色只是默认模板，Policy Engine 最终依据权限声明和资源范围判断。

## 16. 异常与用户反馈

- 模型失败：返回可重试状态或明确错误码，不暴露 Provider 密钥和内部请求。
- Tool 被拒绝：Agent 可以调整方案，但不能重复绕过策略。
- 等待审批：用户持续看到等待原因和有效期。
- 超出预算：立即停止新步骤，保留已完成结果和 Artifact。
- Citation 不可访问：不向用户泄漏标题、路径或资源存在性。
- Langfuse失败：只影响观测，不影响 RunResult。
- SSE 断开：Run 继续执行，客户端从事件序号恢复。

## 17. 功能边界

V1 明确不提供公有 SaaS运营、动态代码上传、任意代码执行、自治多 Agent 网络、拖拽 Graph 编辑和完整 Tool Marketplace。完整范围见 [需求文档](./需求文档.md)。
