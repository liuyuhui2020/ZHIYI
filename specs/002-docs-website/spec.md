# Feature Specification: Official Documentation Website

**Feature Branch**: `codex/002-docs-website`

**Created**: 2026-08-21

**Status**: Ready for Planning

**Input**: User description: "按照建议建设现代官方文档网站，提供品牌首页、导航、搜索、主题、响应式体验和可持续维护的文档入口；本轮不部署。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 快速理解项目并选择下一步 (Priority: P1)

作为第一次访问 ZHIYI 的潜在使用者、开发者或评审者，我希望在首屏快速理解
产品是什么、解决什么问题、当前处于什么阶段，并能进入架构、路线图或文档，
从而判断项目是否值得继续了解。

**Why this priority**: 官网首先必须建立清晰、可信的产品认知；如果访客无法理解
定位和成熟度，后续文档能力没有价值。

**Independent Test**: 让不了解项目的测试者仅浏览首页，在 30 秒内说明产品定位、
当前状态和至少两个可继续访问的入口。

**Acceptance Scenarios**:

1. **Given** 访客首次打开官网，**When** 首屏完成呈现，**Then** 访客能看到 ZHIYI 品牌、核心承诺、当前阶段和主要行动入口。
2. **Given** 产品能力尚未实现，**When** 访客浏览能力与路线图，**Then** 页面明确区分“已建立”“设计目标”和“计划阶段”，不得把规划描述为现有能力。
3. **Given** 访客希望深入了解，**When** 选择架构、路线图或文档入口，**Then** 能到达对应内容且不会进入空白或占位页面。

---

### User Story 2 - 高效浏览和检索项目文档 (Priority: P1)

作为 Agent 平台开发者或项目维护者，我希望通过清晰的分层导航、当前位置提示、
前后篇章关系和全文检索找到需求、功能、架构及开发规范，从而减少在仓库文件树
中反复查找的成本。

**Why this priority**: 文档站的核心价值是发现和阅读知识，而不是只提供营销首页。

**Independent Test**: 从任意核心文档页面出发，测试者能在两次导航操作内访问
另一份核心文档，并能通过标题或关键术语检索到目标页面。

**Acceptance Scenarios**:

1. **Given** 访客位于任意文档页，**When** 查看导航，**Then** 能识别当前文档所属分组、当前位置和可继续阅读的相关页面。
2. **Given** 访客输入“AgentVersion”“幂等”或“设计漂移”等已存在术语，**When** 执行搜索，**Then** 返回包含标题、摘要和目标链接的相关结果。
3. **Given** 搜索没有匹配结果，**When** 结果页或搜索面板显示，**Then** 提供明确的无结果反馈和可恢复操作。
4. **Given** 访客直接打开一个深层文档地址，**When** 页面加载，**Then** 文档内容和导航状态均正确，不依赖先访问首页。

---

### User Story 3 - 在不同设备和偏好下舒适阅读 (Priority: P2)

作为使用桌面、平板、手机或键盘辅助操作的访客，我希望网站在不同屏幕和主题偏好
下都保持清晰、可导航、可阅读，从而不因设备或交互方式被排除。

**Why this priority**: 官网代表项目工程质量，响应式和可访问性属于基础质量而非装饰。

**Independent Test**: 在窄屏、宽屏、键盘导航、浅色和深色偏好下完成首页到文档
搜索的主流程，验证无内容遮挡、无横向溢出且焦点可见。

**Acceptance Scenarios**:

1. **Given** 视口宽度从 320 像素变化到宽屏，**When** 浏览首页和文档页，**Then** 内容不横向溢出，导航可操作，正文保持可读。
2. **Given** 访客仅使用键盘，**When** 依次访问导航、搜索、主题和正文链接，**Then** 顺序符合视觉逻辑，焦点持续可见。
3. **Given** 系统偏好浅色、深色或减少动态效果，**When** 网站加载，**Then** 默认体验尊重偏好，并允许在可用时覆盖主题选择。
4. **Given** 动画或增强脚本不可用，**When** 页面呈现，**Then** 核心内容和导航仍可访问。

---

### User Story 4 - 从单一事实源持续发布文档 (Priority: P2)

作为项目维护者，我希望官网复用仓库内已批准的项目文档，并在链接失效、页面缺失
或规划状态混淆时阻止发布，从而避免官网与 Spec Kit 和长期文档静默漂移。

**Why this priority**: 维护两套手工复制的文档会快速失真，破坏项目已经建立的 SDD 治理。

**Independent Test**: 修改一份受治理源文档后生成网站，确认网站反映同一内容；
再制造一个失效内部链接，确认验证流程失败并指出来源。

**Acceptance Scenarios**:

1. **Given** 受治理源文档已更新，**When** 生成官网内容，**Then** 不需要在第二份正文副本中重复修改。
2. **Given** 文档包含失效内部链接或缺失目标，**When** 执行发布前验证，**Then** 流程失败并报告源文件和目标。
3. **Given** 仓库只有中文内容，**When** 访客浏览语言入口，**Then** 不出现空白英文站或虚假的已翻译状态。
4. **Given** 本轮未获得部署授权，**When** 完成网站构建，**Then** 仅产生可本地验证的成果，不创建公开域名或线上站点。

### Edge Cases

- 浏览器禁用或未能加载增强脚本时，正文、主导航和核心链接仍应可用。
- 搜索关键字包含中文、英文缩写、连字符或大小写差异时，应保持可预测结果。
- 文档标题重复时，搜索结果和导航应包含足够上下文帮助区分。
- 超长代码块、宽表格、Mermaid 图和长英文标识不得破坏窄屏页面。
- 源文档引用仓库根目录文件或同级中文文件名时，链接必须被正确解析。
- 规划能力和已实现能力冲突时，网站必须以当前受治理文档和项目状态为准。
- 未提供英文内容或历史版本时，不展示不可用的语言或版本切换入口。
- 外部徽章、字体或第三方资源不可用时，不得导致核心内容消失。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 网站 MUST 在首页突出展示项目品牌、价值主张、目标受众和当前成熟阶段。
- **FR-002**: 网站 MUST 提供桌面和移动端均可操作的全局导航，覆盖首页、核心概念、架构、路线图、文档和代码仓库入口。
- **FR-003**: 网站 MUST 明确区分已建立的治理能力、尚未实现的产品能力和各里程碑计划。
- **FR-004**: 用户 MUST 能按文档分组浏览需求、功能、技术、项目治理和开发规范。
- **FR-005**: 用户 MUST 能按标题和正文关键字检索所有已发布核心文档，并获得可访问的结果链接与无结果反馈。
- **FR-006**: 文档页面 MUST 提供当前位置、章节导航以及适用的上一篇/下一篇关系。
- **FR-007**: 网站 MUST 支持浅色和深色阅读体验，默认尊重系统偏好并记住用户明确选择。
- **FR-008**: 网站 MUST 在常见手机、平板和桌面宽度下保持完整内容、可操作导航和可读排版。
- **FR-009**: 所有核心交互 MUST 支持键盘操作、可见焦点、语义化名称和跳过重复导航的机制。
- **FR-010**: 动态效果 MUST 尊重减少动态效果偏好，且不得成为理解内容或完成导航的前置条件。
- **FR-011**: 官网正文 MUST 来自仓库内的受治理事实源或明确标识的网站专用内容，不得维护未声明的长期正文副本。
- **FR-012**: 发布前验证 MUST 检查缺失页面、失效内部链接、不可解析内容和规划状态误导。
- **FR-013**: 首页和文档页 MUST 提供准确的标题、描述、分享摘要、规范地址和基础索引信息。
- **FR-014**: 当前版本 MUST 以中文为唯一完整语言；内容与导航结构 MUST 为未来英文版本预留稳定扩展边界，但不得展示空语言入口。
- **FR-015**: 当前版本 MUST 显示方案基线状态，并为未来文档版本保留稳定路径和状态标识，但不得伪造不存在的历史版本。
- **FR-016**: 网站 MUST 在不依赖产品 Runtime、数据库、认证或在线业务服务的情况下完成浏览和搜索主流程。
- **FR-017**: 本 Feature MUST 提供可复现的本地预览、质量检查和发布构建方法，但 MUST NOT 自动部署或公开私有仓库内容。
- **FR-018**: 网站 MUST 不包含分析追踪、广告、第三方登录或不必要的访客数据收集。

### Key Entities

- **Site Page**: 可访问页面，具有稳定路径、标题、描述、内容来源、导航分组和发布状态。
- **Document Source**: 仓库内受治理的事实文档，具有源路径、显示标题和同步规则。
- **Navigation Entry**: 指向页面或外部资源的可排序入口，包含层级、标签和可用状态。
- **Search Entry**: 可检索内容单元，关联页面、标题、摘要、术语和目标地址。
- **Content Status**: 描述内容属于已建立、设计目标或计划阶段的显式状态。
- **Locale Boundary**: 当前可用语言及未来新增语言时保持稳定路由和内容隔离的约束。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 首次访问者能够在 30 秒内准确说明项目定位、当前阶段和至少两个后续入口。
- **SC-002**: 从任意核心页面访问另一份核心文档最多需要两次导航操作。
- **SC-003**: 使用每份核心文档的标题或一个代表性术语进行搜索时，目标页面均出现在首屏结果中。
- **SC-004**: 首页和文档主流程在 320、768、1280 和 1920 像素宽度下均无页面级横向滚动或不可达操作。
- **SC-005**: 仅使用键盘可以完成首页导航、打开搜索、访问结果、切换主题和阅读文档的完整流程。
- **SC-006**: 自动化质量评估中，首页和一份代表性文档页的性能、可访问性、最佳实践和可发现性评分均达到 90 分以上，且无严重可访问性问题。
- **SC-007**: 发布构建对全部内部链接执行验证，已知失效链接检出率为 100%，正常内容零误报。
- **SC-008**: 修改任一受治理源文档后，官网重新生成无需同步编辑第二份长期正文副本。
- **SC-009**: 规划能力、现有能力和仓库阶段在首页、路线图和文档入口中保持一致，不出现把未实现能力描述为已交付的检查发现。
- **SC-010**: 在标准开发环境中，维护者可以使用文档中的命令在 10 分钟内完成依赖准备、质量检查和生产构建。

## Assumptions

- 本轮交付官网源码、本地预览和可发布构建，不购买域名、不配置公开托管、不执行部署。
- 当前仓库仍为私有方案阶段；对外公开前需要单独确认许可证、公开范围和数据暴露风险。
- 中文是首个完整内容语言，英文全文翻译在术语和产品能力稳定后作为独立 Feature 处理。
- 当前只有方案基线，不创建虚假的产品截图、客户 Logo、下载量、版本号或可运行 Quickstart。
- 仓库内 README、`doc/` 文档、Spec Kit 工件和项目宪法继续按照既有优先级作为事实源。
- 网站面向匿名只读访客，不需要账户、评论、个性化或服务端数据。
- 外部代码仓库链接指向当前 GitHub 项目；官网部署地址在获得授权后再确定。
