**Feature Branch**: `codex/006-worker-lease-kernel`

**Created**: 2026-08-26

**Status**: Planned; lease-safety checklist reviewed (40/40)

**Input**: User description: "为 006 Worker Lease Kernel 建立 Spec，从 speckit-specify 开始，暂不实现 LangGraph、Checkpoint、Agent 执行和 Reconciler。"

## Clarifications

### Session 2026-08-26

- Q: 当未来 Worker 持租约推进 Run 时，006 是否必须提供“在同一原子提交中校验当前 fencing token 并写入 Run”的能力？ → A: 006 提供原子租约守卫；未来所有由 Worker 执行产出的新 Run 写入必须在同一提交中验证当前完整权限证明，独立控制面命令仍沿用 004 权限。
- Q: 领取、续租和释放的幂等结果应分别保留到什么程度？ → A: 领取成功或无工作结果持久精确回放；续租和释放不保存无限历史，通过当前 token 与 lease_version 条件执行并从当前租约状态确认结果。
- Q: 006 应建立怎样的生产租约时长与心跳节奏？ → A: 租约允许 10–30 秒且默认 30 秒；续租截止建议不得晚于所选租约时长的三分之一。
- Q: 006 对已失去有效租约的 `running` Run 应提供什么只读观测能力？ → A: 提供租户级有界分页查询和单 Run 查询；自然到期或当前持有者主动释放都形成只读恢复候选，但不修改任何状态。
- Q: 完整领取收据应保留多久，过期领取标识应如何处理？ → A: 完整收据保留到领取标识签发时间后的 24 小时；超过窗口返回 `idempotency_expired` 且不得领取新 Run，未来偏差超过 60 秒则输入无效。
- Q: 并发领取中的“持续可领取且不得无限期跳过”应如何界定？ → A: 该保证适用于始终满足领取条件、未被外部或不合规事务持续占锁的 Run；平台自身领取事务必须使用固定顺序、有限锁与语句超时并在每次新领取时从队头重新探测。`SKIP LOCKED` 快路径将返回无工作时，必须执行一次受同一超时约束的阻塞式队头探测；持续外部持锁因此返回可观测存储故障，而不是被伪装成无工作。
- Q: 006 如何满足日志、指标和追踪的宪法要求而不提前实现 Langfuse/OpenTelemetry？ → A: 每次进入租约仓储公共操作的调用都必须在事务与锁释放后生成一个不可变、脱敏的终态观测，并通过强制注入的框架无关端口分别发送到日志、指标和追踪三个独立通道；通道失败不得改变租约结果或触发写入重试。006 只定义并调用端口，不实现 Langfuse/OpenTelemetry 导出、后台队列或部署装配。

### Session 2026-08-27

- Q: 固定本地环境通过的绝对延迟门禁应如何在异构共享 CI runner 上执行？ → A: SC-008 只在资源与数据库配置均已固定并记录的性能验收环境执行，阈值、样本量、并发度和持久性语义均不得降低。异构共享 CI 必须完整运行全部非性能 PostgreSQL 验收、证明 005/006 性能模块可被独立收集且不会混入功能选择，但不得把共享 runner 的绝对延迟作为产品性能通过或失败的依据。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 独占领取一个待执行 Run (Priority: P1)

作为 Runtime Worker 的开发者，我希望一个 Worker 能在明确租户边界内领取一个排队中的
Run，并获得短期、独占且可验证的执行所有权，从而让多个 Worker 可以安全竞争工作而不
会同时认为自己拥有同一个 Run。

**Why this priority**: 独占领取是异步 Worker、恢复和水平扩展的共同前提；如果所有权本身
不可靠，后续任何执行、Checkpoint 或恢复逻辑都会建立在竞态之上。

**Independent Test**: 准备一个排队 Run，让至少 20 个独立 Worker 身份同时发起领取，验证
恰好一个请求得到当前租约，其他请求得到无可领取工作；Run 的生命周期状态、版本、事件
和命令收据均不因领取而变化。

**Acceptance Scenarios**:

1. **Given** 一个没有有效租约的排队 Run，**When** 一个获授权的 Worker 发起领取，**Then** 返回绑定该租户、Run、Worker、领取命令和有限有效期的唯一当前租约。
2. **Given** 一个排队 Run 正被多个 Worker 并发领取，**When** 所有领取请求完成，**Then** 至多一个 Worker 获得该 Run 的当前租约，其他 Worker 不会收到可用于该 Run 的有效令牌。
3. **Given** 同一租户内有多个可领取 Run，**When** Worker 在无并发争用时连续领取，**Then** 平台按稳定的排队顺序选择工作，已持有有效租约的 Run 不会被再次返回。
4. **Given** 一个领取成功的 Run，**When** 读取其生命周期事实，**Then** Run 状态、版本、事件、预算、结果和 004 命令收据均保持领取前的值。

### User Story 2 - 续租、释放与 fencing 旧所有者 (Priority: P1)

作为 Worker 实现者，我希望只有仍持有当前租约令牌的 Worker 才能续租或证明执行权限，
并能在不再需要工作时主动释放租约，从而让失去所有权的旧进程立即停止启动新工作。

**Why this priority**: 租约只有同时具备有限时效与 fencing 才能形成真实互斥；单独记录
Worker 标识或过期时间无法阻止暂停后恢复的旧进程继续操作。

**Independent Test**: 对一个当前租约依次执行有效续租、重复续租、错误令牌续租、到期后
续租、主动释放和释放后旧令牌校验，验证只有当前令牌可以延长权限，重复操作不会重复延长，
任何失效令牌都不能重新获得权限。

**Acceptance Scenarios**:

1. **Given** 一个尚未过期的当前租约，**When** 同一 Worker 使用当前令牌和当前 lease_version 续租，**Then** 心跳与 10–30 秒范围内的新有效期按平台权威时间更新、lease_version 递增一次，并返回不晚于租期三分之一的续租截止建议，Run 生命周期事实不变。
2. **Given** 一个当前租约，**When** 其他 Worker、错误令牌或已被替换的旧令牌尝试续租或校验权限，**Then** 请求被稳定拒绝且当前租约不变。
3. **Given** 一个租约已经到期，**When** 原 Worker 尝试续租，**Then** 租约不会被复活，原 Worker 被判定为不再拥有执行权限。
4. **Given** 一个当前租约，**When** 持有者主动释放，**Then** 该令牌立即失效；若 Run 仍处于排队状态，后续新领取可以获得不同令牌和更高尝试序号。
5. **Given** 一个续租或释放操作已经成功但响应丢失，**When** 原 Worker 使用同一 token 和旧 lease_version 确认或重试，**Then** 返回当前租约权限状态，不再次延长有效期、不重复释放，也不改变尝试序号。
6. **Given** Worker 准备提交一个由其执行产生的 Run 变更，**When** 当前 token 校验、Run 版本判定和该变更在同一原子边界内成功，**Then** 变更按 004 契约提交；任一判定失败时 Run、事件、命令收据和租约均不发生部分变化。

### User Story 3 - 在进程故障与结果未知后安全收敛 (Priority: P1)

作为平台维护者，我希望租约在 Worker 进程退出和存储响应不确定时仍能保留可判定的持久
事实，并允许排队 Run 在租约到期后被新 Worker 安全领取，从而避免永久占用或双重所有权。

**Why this priority**: Worker 故障是正常运行条件；如果租约只存在于进程内，或调用方在
提交结果未知时用新命令盲目重试，就可能同时遗失工作和制造两个所有者。

**Independent Test**: 领取后销毁原 Worker 访问实例，在到期前和到期后分别由新实例领取；
同时覆盖领取、续租和释放的提交前故障、确定回滚与提交确认不明窗口，验证领取精确重放
以及续租/释放的当前状态确认最终收敛到一个租约事实。

**Acceptance Scenarios**:

1. **Given** Worker 在领取成功后退出，**When** 新实例在租约到期前尝试领取同一排队 Run，**Then** 新实例不能获得该 Run。
2. **Given** 排队 Run 的租约已经到期，**When** 新 Worker 发起领取，**Then** 新 Worker 获得不同令牌和更高尝试序号，旧令牌永久失效。
3. **Given** 领取响应在提交确认阶段丢失且原命令仍在 24 小时回放窗口内，**When** 原 Worker 使用相同领取命令标识和相同意图重放，**Then** 返回原领取结果而不是占用另一个 Run。
4. **Given** 一个处于 `running` 的 Run 因自然到期或当前持有者主动释放而失去租约，**When** 在所属租户内按 Run 查询或分页读取失效工作，**Then** 租约内核只报告该恢复候选并拒绝旧令牌，不把 Run 重新分配、回退状态或尝试继续执行。
5. **Given** 存储故障能够或不能确认写入结果，**When** 租约操作失败，**Then** 分别得到确定未提交或提交结果未知的稳定失败；领取只能使用原命令标识与原意图精确重放，续租或释放只能读取当前 token 与 lease_version 后按条件确认。

### User Story 4 - 租户安全地观察和演进租约事实 (Priority: P2)

作为安全与运维人员，我希望租约的读取、领取和维护始终受租户边界约束，结构能够独立
升级，并且日志与指标只暴露必要的协调信息，从而在不泄露令牌、资源归属或业务载荷的
前提下排查争用、过期和存储故障。

**Why this priority**: 租约令牌是执行权限凭证，多租户错误或日志泄漏都可能把并发缺陷
升级为越权执行；持久结构也必须继续遵守 005 已建立的部署安全边界。

**Independent Test**: 使用两个租户的同名 Run、Worker 和领取命令标识执行正向与跨租户负向
矩阵，触发全部成功、冲突、过期和存储错误，使用记录型观测端口验证每次操作分别产生一个
脱敏日志、指标和追踪终态，再在一次性环境演练结构升级；验证无跨租户影响、无敏感标记
泄漏、观测通道故障不改变业务结果且应用启动不改变结构。

**Acceptance Scenarios**:

1. **Given** 两个租户拥有相同 Run 标识，**When** Worker 在各自授权租户内领取和续租，**Then** 两组租约完全独立，任何请求都不能读取或改变另一租户的事实。
2. **Given** 一个 Run 或租约只存在于其他租户，**When** 当前租户查询或操作，**Then** 公开结果与本租户资源不存在不可区分，不披露真实所有者、Worker 或令牌。
3. **Given** 成功、无工作、冲突、过期和存储故障路径，**When** 检查公开错误及观测端口，**Then** 每次进入公共仓储操作的调用分别产生一个带稳定操作、阶段、结果和适用安全标识的终态日志、指标及追踪记录，但不存在原始租约令牌、连接凭据或 Run 业务载荷。
4. **Given** 一个受支持的产品数据环境，**When** 应用或 Worker 进程启动，**Then** 它只验证结构兼容性，不自动建立、升级或回退租约结构。
5. **Given** 任一日志、指标或追踪通道抛出异常，**When** 租约操作已经得到确定结果，**Then** 该结果仍按原语义返回，其他观测通道仍被独立尝试，且不重试数据库写入或在锁内调用导出器。

### Edge Cases

- 租约在平台权威时间恰好到达到期点时即视为过期；Worker 本地时钟不能延长、缩短或恢复权限。
- 领取或续租未指定租约时长时使用 30 秒；指定值小于 10 秒或大于 30 秒时必须在持久访问前拒绝，不能静默截断、扩大或使用部署私有默认值替代。
- 同一领取命令标识和相同意图只绑定第一次确定的成功或无工作结果；重放时即使出现更早或新的排队 Run，也不能改选。无工作结果不产生所有权，后续轮询必须使用新的领取命令标识。
- 领取命令标识的不可变签发时间早于平台权威时间 24 小时及以上时，只能返回 `idempotency_expired` 且不得读取旧收据或领取新 Run；签发时间晚于权威时间超过 60 秒时必须作为输入无效拒绝。
- 同一租户内，同一领取命令标识被用于不同 Worker、时长或其他领取意图时必须作为幂等冲突拒绝，不能执行新意图；不同租户可以独立使用相同标识。
- 领取请求在选中 Run 后与取消、终态转换或其他状态变化竞争时，必须对同一当前事实作出单一结果；非排队 Run 不能获得新租约。
- token 在 Worker 读取租约后、Run 写入提交前到期或被替换时，原子租约守卫必须按提交时的当前事实拒绝该写入；先读取再写入不能替代同一提交内的校验。
- 当前租约对应的 Run 若变为等待或终态，租约立即不再授予执行权限且不能续租；持有正确令牌的释放仍可进行安全清理，但不得改变 Run 状态。
- `running` Run 的租约自然到期或被当前持有者主动释放只能形成失效恢复候选。本 Feature 不判断 Checkpoint 是否可用、不选择恢复位置、不转移执行所有权，也不改变 Run 状态。
- 失效恢复候选查询必须要求单一 tenant_id；页大小小于 1 或大于 1,000、游标无效、游标属于其他租户时必须在有界查询前拒绝。第一页固定数据库 `as_of`，新失效记录不得进入后续页；候选在翻页期间转为等待或终态时允许从后续页消失，但不得产生重复、倒序、跨租户泄漏或 OFFSET/全表回退。SC-013 的零缺口只在候选集合不变的验收数据集中成立。
- 续租或释放提交后响应丢失时，旧 lease_version 只能用于确认当前权限状态，不能再次推进版本或按重试时间延长租约；多个请求使用同一当前 lease_version 时至多一个成功。
- 释放、到期或被新租约替换后，旧令牌永久失效；即使旧 Worker 在网络暂停后恢复，也不能通过旧心跳重新成为当前所有者。
- 无可领取 Run 是正常空结果，不是存储失败；资源存在于其他租户时也不能通过空结果、错误内容或诊断字段推断出来。
- 无效租约时长、空 Worker 标识、空领取命令标识、无效 lease_version、格式错误令牌或缺失租户上下文必须在访问持久事实前拒绝。
- 数据记录出现多个当前租约、不递增的尝试序号、无效时间关系或无法验证的引用时，必须返回稳定的数据损坏失败，不能猜测一个所有者继续工作。
- 在提交确认前断连时，能证明未提交与无法确认结果必须区分；领取结果未知时不得换用新命令标识，续租或释放结果未知时不得在未读取当前租约前按新的当前时间盲目重试。
- 租约操作量可能远高于 Run 生命周期事件量；验收必须覆盖并发心跳与领取压力，但不能通过弱化 fencing、租户隔离或持久性换取吞吐。
- `SKIP LOCKED` 快路径找不到可领取 Run 时不能直接确定无工作；同一短事务必须再按稳定顺序执行一次有界阻塞队头探测。探测获得锁后重新校验资格，等待超时则返回 `storage_unavailable`，只有确认不存在符合条件的队头后才能持久化无工作收据。
- 日志、指标或追踪适配器失败不能改变已经确定的领取、读取、续租、释放、观察或守卫提交结果，也不能在数据库事务、连接或行锁仍活动时调用外部导出。
- 共享 CI runner 的 CPU、I/O 或邻居负载与固定性能环境不一致时，不得通过提高阈值、减少样本、降低并发或关闭持久性来消除波动；该 runner 只执行非性能 PostgreSQL 功能选择并验证性能选择非空且隔离，绝对延迟必须回到已记录的固定环境判定。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 平台 MUST 提供独立于 Agent 执行框架的 Worker Lease Kernel，在持久、共享的产品事实上完成排队 Run 的领取、租约续期、权限校验、主动释放和过期判定。
- **FR-002**: 每个领取请求 MUST 显式携带已授权的单一租户边界、稳定 Worker 身份和在该租户内唯一且包含不可变签发时间的领取命令标识，并 MAY 指定 10–30 秒的租约时长；未指定时 MUST 使用 30 秒。单次请求 MUST 最多领取一个 Run。
- **FR-003**: 新租约 MUST 只授予当前处于 `queued` 且没有未过期当前租约的 Run。`waiting_approval`、`waiting_resolution`、`running` 和所有终态 Run MUST NOT 被新领取请求直接分配。
- **FR-004**: 同一租户内存在多个可领取 Run 时，无并发争用的选择 MUST 遵循稳定的先入队先领取顺序和确定性并列规则；并发领取 MAY 因正在竞争的较早 Run 而以不同顺序完成，但 MUST NOT 无限期跳过“持续可领取”的较早 Run。“持续可领取”指在一次完整排空验收期间始终为 `queued`、不存在有效租约、未被取消或转态，并且没有外部或不合规事务持续占锁；平台事务造成的暂时锁竞争不取消其资格，锁释放后每个新领取 MUST 从队头重新探测。平台自身领取事务 MUST 使用固定顺序、1–5,000 毫秒锁超时、1–10,000 毫秒语句超时且语句超时不得小于锁超时；默认二者均为 5,000 毫秒，超界配置在构造期拒绝。`SKIP LOCKED` 快路径准备返回无工作时 MUST 在同一短事务内执行一次受上述超时约束的阻塞式队头探测并重新校验；持续外部持锁 MUST 因该探测返回可观测 `storage_unavailable`，不得伪装为无工作。本 Feature 不提供优先级、延迟任务、跨租户公平调度或批量领取。
- **FR-005**: 领取的资格判定、当前租约冲突判断和新租约建立 MUST 形成一个不可分割结果；并发请求 MUST NOT 为同一 Run 建立两个同时有效的当前租约。
- **FR-006**: 每个成功租约 MUST 绑定 tenant_id、run_id、worker_id、领取命令标识、不可猜测的非空 fencing token、获取时间、到期时间、最近心跳时间、该 Run 单调递增的 attempt_no，以及永不重置的 lease_version。首次所有权的 attempt_no 与 lease_version 均为 1；此后每次新所有权二者各递增一次，每次成功续租或释放只将 lease_version 递增一次。旧权限证明由 token、claim_id、attempt_no 与当前租约事实共同判定；即使随机 token 值发生碰撞，也 MUST NOT 使旧权限证明重新生效。
- **FR-007**: 租约 MUST 跨进程和访问实例持久存在。进程退出、连接池重建或新实例启动 MUST NOT 提前释放、复制或延长租约。
- **FR-008**: 平台 MUST 使用单一权威时间判定租约有效性。领取和续租的租约时长 MUST 限于闭区间 10–30 秒且默认 30 秒；超界值 MUST 拒绝而不是截断。到期边界及之后的租约 MUST 立即失效，Worker 提供的本地时间 MUST NOT 成为权限依据。
- **FR-009**: 当前租约 MUST 在租户、Run、Worker 和 fencing token 全部匹配、尚未释放或替换、尚未到期且 Run 仍处于 `queued` 或 `running` 时，才授予 Worker 执行权限。
- **FR-010**: 只有符合 FR-009 的当前持有者才能使用当前 lease_version 续租。一次成功续租 MUST 按 FR-008 更新最近心跳和确定的新到期时间，将 lease_version 递增一次，并返回“捕获的数据库时间 + 所选时长三分之一、向下取整到微秒”的下一续租截止建议，但 MUST NOT 改变 token 或 attempt_no；到期租约、旧 lease_version 或并发失败请求 MUST NOT 续租或再次延长。并发有效心跳可以推进 lease_version，但不能单独使同一 token 的 FR-016 守卫写入失效。
- **FR-011**: 当前持有者 MUST 能使用当前 lease_version 主动释放租约。成功释放 MUST 将 lease_version 递增一次并立即使 token 失效且不得改变 Run；重复释放或旧 lease_version MUST 只返回当前非授权状态。若 Run 仍为 `queued`，后续领取 MUST 建立新 token 并递增 attempt_no。
- **FR-012**: Run 进入等待状态或终态后，既有租约 MUST 立即不再授予执行权限或接受续租；使用匹配 token 的释放 MAY 清理租约事实，但 MUST NOT 改写 Run 生命周期。
- **FR-013**: 对已到期或已释放的 `queued` Run，新领取 MUST 能建立新租约并永久 fence 旧权限证明。对因自然到期或主动释放而失去有效租约的 `running` Run，本 Feature MUST 提供按 tenant_id 与 run_id 的单项查询，以及 tenant_id 内按 `authority_ended_at = COALESCE(released_at, lease_expires_at)` 和稳定 Run 身份排序的有界游标分页；默认页大小为 100，允许 1–1,000。查询 MUST 只返回权威时间下仍为 `running` 且 `authority_ended_at <= as_of` 的恢复候选，以及 tenant_id、run_id、attempt_no、lease_version、acquired_at、heartbeat_at、authority_ended_at 和 `expired|released` 原因；不得返回 Worker/claim/token/digest或 Run 业务字段，不得跨租户列举、重新领取、改变状态或启动恢复。
- **FR-014**: 每个领取 MUST 使用租户内唯一的稳定命令标识绑定规范化领取意图与第一次确定的成功或无工作结果。规范化意图版本 1 MUST 完整包含 Worker 身份与默认值已展开的租约时长；tenant_id 是幂等键作用域，claim_id 是该作用域内的命令键。未来新增任何影响领取选择或结果的意图字段 MUST 先提升意图格式版本，旧 claim_id 不得按新格式复用。领取标识中的签发时间与平台权威时间相比，未来偏差 MUST NOT 超过 60 秒；超过时作为输入无效拒绝。相同租户、相同标识和相同意图在 FR-015 窗口内重放 MUST 返回原领取结果；同一租户内相同标识与不同领取意图 MUST 返回稳定幂等冲突，不同租户 MAY 独立使用相同标识。
- **FR-015**: 成功和无工作的完整领取收据 MUST 保留到领取标识签发时间后的 24 小时，且在窗口内不因租约到期、释放、替换或进程重启而删除。窗口内的领取重放 MUST 返回第一次绑定的不可变字段（成功时包括原 token）并重新计算 `currently_authoritative`，或返回第一次确定的无工作结果，不得因队列变化改选其他 Run。签发时间早于平台权威时间 24 小时及以上的领取标识 MUST 返回稳定 `idempotency_expired`，不得读取已过期收据、当作新命令或领取 Run；因此完整收据 MAY 在窗口结束后删除且不要求永久逐标识 tombstone。006 不实现清理任务或物理保留上限：过期收据中的原 token 可能在数据库及备份中继续存在但永不恢复执行权限；这是仅限一次性/本地/CI 与当前 M0 预生产数据库信任边界的显式风险接受，生产启用 MUST 先通过后续 Spec 建立带 SLO 的删除或加密/密钥轮换方案。正常的无工作结果 MUST NOT 建立租约；后续新一轮轮询 MUST 使用新的领取命令标识。
- **FR-016**: 本 Feature MUST 提供原子租约守卫。“Worker-owned Run 写入”指由某次 Worker 执行产出、只有该执行仍拥有当前租约才合法的新生命周期事实；它必须使用更强的守卫端口。由独立控制面权限产生且不声称来自该 Worker 执行的创建、取消或期限强制等 004 命令继续使用普通 004 权限，不能借命令名称绕过实际执行来源。每个 Worker-owned 写入 MUST 在同一提交边界内，在锁定当前 Run 与租约后校验 tenant_id、run_id、worker_id、claim_id、attempt_no、当前 fencing token、权威到期时间、允许持有租约的 Run 状态和 004 预期版本，再按 004 契约提交 Run、零或一条事件及 CommandReceipt；任一校验、冲突或存储失败 MUST 留下零部分更新。独立的预先权限查询 MUST NOT 替代该提交时校验。已存在且 004 意图匹配的 CommandReceipt 必须沿用普通 004 的只读重放优先级，不因当前租约失效而拒绝，也不新增永久守卫绑定；该重放不产生新执行权限或写入。
- **FR-017**: 每个权限读取和条件租约结果 MUST 提供框架无关的 `may_start_new_work` 安全信号；只有提交时刻确认当前授权的结果可为 true。token 不再有效、续租未应用、`commit_outcome_unknown`、存储失败或租约到期时该信号 MUST 为 false，调用方 MUST 停止启动新的执行步骤，直至按 FR-021 收敛后重新获得 true。本 Feature 不负责中断已开始的模型、Tool、Graph 节点或其他外部副作用。
- **FR-018**: 所有领取、读取、续租、释放、权限校验、幂等和过期候选操作 MUST 显式受 tenant_id 约束；跨租户资源与本租户不存在 MUST 返回不可区分的公开结果，且不得泄露资源是否存在或真实归属。
- **FR-019**: fencing token MUST 作为执行权限凭证处理，只能返回给已授权的对应 Worker 协调路径；公开异常、日志、指标、追踪和可打印表示 MUST NOT 包含原始 token、连接凭据、原始查询、完整 Run 输入/输出、最终答案或隐藏推理。
- **FR-020**: 平台 MUST 提供稳定且脱敏的无工作、输入无效、幂等冲突、`idempotency_expired`、租约非当前、租约已过期、存储不可用、提交结果未知、数据损坏和结构不兼容结果；这些分类不得互相替代或伪装为成功。
- **FR-021**: 租约写入在能够证明未提交时 MUST 返回 `storage_unavailable`，无法证明提交或回滚时 MUST 返回 `commit_outcome_unknown`。内核 MUST NOT 自动重试写入。领取结果未知时，调用方只能在 FR-015 窗口内以原命令标识和原意图在新连接上精确重放，窗口外只能得到 `idempotency_expired`；续租或释放结果未知时，调用方 MUST 先读取同一证明的当前 token、attempt_no、lease_version、有效期、Run 状态和授权状态。仅当 token/attempt 未变、原预期版本仍为当前版本、租约仍未释放且未到期、Run 状态仍允许该操作时，才可用原时长与原预期版本重试同一条件变更；版本已推进只能确认，token/attempt 改变必须永久 fence，确认期间到期或 Run 转态必须停止，第二次存储失败仍返回安全失败且 `may_start_new_work=false`，不得按新的当前时间盲目延长。守卫提交结果未知时只用原 004 command_id 与原生命周期意图重放：若收据存在则按 004 回放，若不存在则新路径仍必须通过当前租约守卫。
- **FR-022**: 单独的领取、续租、释放或其安全确认 MUST NOT 修改 Run 状态、版本、预算、累计用量、事件、RunResult 或 004 CommandReceipt；领取收据以及租约上的 token/lease_version 条件事实 MUST 与 Run 生命周期命令事实保持逻辑分离。通过 FR-016 原子守卫提交的 Run 变更仍完全遵守 004 命令、事件、收据和版本语义，不得由租约内核创造新的生命周期行为。
- **FR-023**: 多实例互斥、唯一当前租约、尝试序号、幂等和 fencing 保护 MUST 在共享持久事实层成立，不能只依赖单进程锁、内存缓存、Worker 自律或调用方先查后写。
- **FR-024**: 平台 MUST 提供独立、可重复、可识别兼容版本的租约结构升级步骤；普通应用和 Worker 启动 MUST NOT 自动建立、升级、回退或修复持久结构。
- **FR-025**: 租约结构演进 MUST 评估滚动升级期间新旧应用的兼容性，并提供明确的数据影响、回退或备份恢复步骤；不兼容结构必须在读取业务事实前安全失败。
- **FR-026**: 验收 MUST 使用真实共享持久环境和多个独立访问连接证明并发、进程重开、到期、幂等、事务故障、租户隔离及结构升级；内存替身或行为桩不能替代这些证明。
- **FR-027**: 本 Feature MUST 保持 004 Run Lifecycle Kernel 和 005 PostgreSQL RunRepository 的既有领域状态、版本、事件、命令收据、错误边界和多租户语义；发现冲突时 MUST 先同步规格与设计，不能由租约实现静默改写。
- **FR-028**: 本 Feature MUST NOT 实现 LangGraph、任何 Checkpoint 读写或恢复、Agent/模型/Tool/Graph 节点执行、Worker 轮询与执行循环、Reconciler 扫描修复、REST/SSE、SDK、Model Gateway 集成、Approval、Context、Memory、RAG 或 Langfuse。
- **FR-029**: 本 Feature MUST NOT 声称已经实现 Worker 故障后 30 秒内接管、Run 从 Checkpoint 恢复、永久卡住 Run 修复或 100 个活跃 Run 执行容量；这些结果依赖被明确排除的后续能力。
- **FR-030**: `issue_claim_id`、领取、权限读取、续租、释放、单项/分页失效观察和原子守卫提交的每次公共仓储调用 MUST 在事务、连接与锁释放后构造一个不可变终态观测，并通过强制注入的框架无关观测端口分别发送到日志、指标和追踪三个独立通道。观测 MUST 包含稳定操作名、事务阶段、稳定结果/错误码、适用的调用方安全标识、重放/空结果/争用标志和有界延迟桶；MUST NOT 包含 FR-019 禁止字段或从跨租户事实发现的身份。任一通道失败 MUST NOT 改变业务结果、阻止其他通道、触发数据库写重试或在持锁期间调用外部导出。本 Feature 不实现 Langfuse/OpenTelemetry 导出器、后台遥测队列或部署装配。
- **FR-031**: PostgreSQL 验收 MUST 明确区分功能正确性与绝对延迟两类证据。绝对延迟只在资源、数据库镜像、连接池与超时均已固定和记录的合格环境执行，并 MUST 保持 005/006 原阈值、预热、样本量、并发度、持久性和安全语义。异构共享 CI MUST 证明两类验收均存在且互不混入，以零跳过运行全部非性能 PostgreSQL 功能验收；共享 CI 不得据此声称 SC-008 通过，也不得把其绝对延迟波动判为产品性能回归。

### Key Entities

- **Worker Identity**: 平台认可的 Worker 实例身份，用于把领取和续租动作归属于一个执行者；它不是租户用户身份，也不能单独证明执行权限。
- **Lease Claim Command**: Worker 在一个授权租户内请求一个排队 Run 的稳定意图，包含租户内唯一且带不可变签发时间的命令标识、Worker 身份和可选的 10–30 秒租约时长；未指定时使用 30 秒，第一次确定后在 24 小时窗口内绑定所选 Run 与初始租约结果，或绑定当时的无工作结果。
- **Worker Lease**: 某个 Worker 对一个 Run 的短期协调所有权，包含租户、Run、Worker、fencing token、获取/心跳/到期时间、attempt_no、lease_version 和当前有效性；它不等同于 Run 生命周期状态。
- **Lease Claim Receipt**: 领取命令的持久确定性处理事实，绑定租户、领取命令标识、规范化意图和成功或无工作结果，在领取标识签发后的 24 小时内支持进程重启或提交结果未知后的精确重放；它与 004 CommandReceipt 逻辑分离，窗口结束后可删除。
- **Conditional Lease Mutation**: 续租或释放使用当前 token 与 lease_version 执行的单步条件变更；成功只推进一次 lease_version，失败或重复请求只返回当前授权状态，不保存无限的心跳收据历史。
- **Atomic Lease Guard**: 在一个 Worker-owned Run 写入的提交边界内，基于当前 Run 与租约事实、权威时间、调用方 token 和预期版本作出允许或拒绝，并保证租约校验与 004 原子提交不可分割；它不执行 Agent 工作。
- **Inactive Running Lease Observation**: 一个 `running` Run 因自然到期或主动释放而失去有效租约的恢复候选事实，可在所属租户内按 Run 查询或通过固定 `as_of` 的有界稳定游标分页读取；本 Feature 只允许观察，不包含 Worker/claim/token 信息、跨租户扫描、重新分配、状态修复、Checkpoint 定位或执行恢复。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对至少 100 个相互独立的单 Run 竞争组，每组由至少 20 个独立 Worker 身份同时领取，恰好一个请求获得当前租约；重复当前所有者、重复 token、重复 attempt_no 和 Run 生命周期变化数量均为 0。
- **SC-002**: 在 100 个排队 Run、20 个并发 Worker、无外部永久锁且平台事务使用 FR-004 默认超时的领取验收中，每个 Run 至多拥有一个当前租约；对整个排空期间始终为 `queued`、无有效租约且未取消/转态的 Run，连续使用新领取命令直至队列为空后，遗漏和重复领取数量均为 0。另在无并发争用的 100 个 Run 验收中，偏离稳定排队顺序的数量为 0；暂时受平台锁竞争的较早 Run 在锁释放后最终未被领取的数量为 0。
- **SC-003**: 对至少 100 个完整租约周期执行领取、有效续租、重复续租、错误 token、到期、旧 token、释放、重新领取及原子守卫写入矩阵，未授权续租、权限校验或 Worker-owned Run 写入的成功数为 0；每次新所有权的 attempt_no 严格递增且 token 不重复，守卫失败产生的 Run、事件、CommandReceipt 或租约部分变化数量为 0。另对未指定、10 秒、30 秒、低于 10 秒和高于 30 秒的时长边界验收 100 次，默认值、合法接受、超界拒绝及续租截止建议的准确率均为 100%。
- **SC-004**: 对领取执行至少 100 次同命令并发重放，只产生一个持久领取结果；相同命令标识不同意图的拒绝率为 100%，领取重放改选其他 Run 的数量为 0。对签发时间位于 24 小时窗口内、恰好到达窗口边界、超过窗口，以及未来 60 秒边界内外的标识各执行至少 100 次验收，精确重放、`idempotency_expired` 和输入无效分类准确率均为 100%，过期标识领取新 Run 的数量为 0。对续租和释放分别让至少 100 组并发请求使用同一当前 lease_version，每组成功推进版本的请求数为 1，重复延长、重复释放和无限历史收据数量均为 0。
- **SC-005**: 对领取、续租、释放和原子守卫提交的提交前、确定回滚与提交确认不明窗口分别执行至少 100 次可重复故障验收，错误分类准确率为 100%；领取使用原命令精确重放，续租和释放通过当前 token/attempt_no/lease_version/Run 状态确认，守卫提交通过原 004 命令重放或重新执行当前守卫来确认，最终均收敛到一个确定事实，双重所有权、重复延长和部分写入数量为 0。
- **SC-006**: 在领取后销毁原访问进程并建立新实例的至少 100 次验收中，到期前错误接管数为 0；到期后的 `queued` Run 均可被新命令领取，旧 token 恢复权限数为 0。

## Assumptions

- 004 Run Lifecycle Kernel 与 005 PostgreSQL RunRepository 是本 Feature 的上游事实源；006 复用其 Run 身份、状态、租户隔离、原子提交和稳定存储错误语义，不重新设计生命周期。
- PostgreSQL 已是项目批准的首期产品事实源；租约作为独立逻辑实体存在，具体表结构、索引、事务语句和代码接口由规划阶段决定。
- Worker 身份及其允许访问的 tenant_id 由可信部署与未来认证边界提供；本 Feature 不实现 OIDC、RBAC、Worker 注册或密钥分发。UUIDv7 claim_id 只提供租户内幂等键和不可变签发时间，不是能力凭证；可信调用方即使构造一个语法与时间均有效的 UUIDv7，也只能发起普通领取，不能绕过队列资格、租约互斥或 fencing。来自非可信/被入侵调用方的认证与隔离属于该外部部署边界，006 不把 UUID 不可伪造作为安全前提。
- 每个领取命令只请求一个租户的一项工作。Worker 并发容量、预取、批量领取、优先级和跨租户公平策略由后续调度 Feature 定义。
- 稳定排队顺序默认以 Run 首次进入 `queued` 的 `updated_at` 为主，并使用稳定 Run 身份处理同时入队；004 当前状态机不会返回 `queued`。如果未来增加 requeue、优先级或延迟调度，必须先新增独立 `queued_at`/调度事实并更新 006 Spec/Plan/Data Model，不能继续假设 `updated_at` 等于入队时间。
- 产品租约时长固定允许 10–30 秒并默认 30 秒；部署不能改变默认值或扩大范围。006 只返回不晚于租期三分之一的续租截止建议，不创建负责按时心跳的 Worker 循环。
- 领取收据的行为回放窗口有界为 24 小时；领取标识的不可变签发时间使平台能在不保留永久逐标识 tombstone 的情况下拒绝过期重放。006 没有物理清理/加密能力，因此不声称原 token 的数据库或备份保留时长有上限，也不具备生产启用资格；续租和释放不建立逐操作永久收据，其未知结果由当前租约状态收敛。
- PostgreSQL 主机墙上时间是唯一权限时钟，但不是单调时钟。006 代码与测试负责人只证明 Worker 时钟不参与判定；平台/数据库运维负责人必须在任何生产启用前监控 NTP 偏差和向后跳变并配置告警，该上线能力不由本 Feature 实现或验收为已存在。
- 本 Feature 可以提供供未来 Worker 调用的领取与权限边界，但不创建常驻 Worker 进程，也不触发任何模型、Tool 或 Graph 行为。
- `running` Run 的安全接管依赖兼容 Checkpoint、恢复策略与 Reconciler；在这些能力建立前，过期只能被观察和告警，不能由 006 猜测恢复。
- 租约结构升级由发布流水线或运维人员显式执行；测试使用一次性、非生产环境，任何生产迁移、备份或部署仍需单独授权。
- 006 的框架无关观测端口只暴露安全终态事实；实际 OpenTelemetry/Langfuse 导出、批处理、采样、告警和部署装配属于后续 Runtime/Observability Feature。006 验收使用记录型通道证明调用、隔离和脱敏，不能据此声称生产观测后端已经部署。
